# OctoAcme Project Management Overview

## Purpose
Provide a concise, shareable introduction to how OctoAcme runs projects so new teammates can quickly understand our approach, roles, and key artifacts.

## Scope
Applies to all cross-functional projects that deliver product features, services, or integrations.

## Principles
- Customer-first: prioritize customer value and usability.
- Iterative delivery: deliver small, testable increments.
- Clear ownership: each project has a named Project Manager (PM) and Product Lead.
- Data-informed decisions: measure impact and iterate based on evidence.
- Psychological safety: encourage feedback and learning.
- Cross-functional collaboration: involve all necessary expertise early and often.

## Core Roles

### Project Manager (PM)
Coordinates delivery, schedules, risk, and communications across teams and stakeholders.

### Product Manager (PdM)
Defines outcomes, prioritizes backlog, measures success, and advocates for customer value.

### Developers
Implement features, collaborate on design and testability, and own code quality.

### UX Designer
Ensures user-centered design, conducts research, and validates usability throughout delivery.

### QA / Testing
Validates quality and acceptance criteria; identifies defects and quality risks.

### Subject Matter Expert (SME)
Provides specialized domain knowledge (business, technical, compliance, security) to inform decisions and validate solutions.

### DevOps Engineer
Manages infrastructure, CI/CD pipelines, and deployment automation; enables fast, reliable releases.

## Key Artifacts
- Project Charter / One-pager
- Roadmap and Release Plan
- Sprint/Iteration Backlog
- Acceptance Criteria & Definition of Done
- Risk Register
- Retrospective notes and action items
- Cross-functional collaboration agreements (see `docs/octoacme-cross-functional-collaboration.md`)

## Lifecycle (high-level)
1. **Initiation:** problem statement, stakeholders, high-level timeline.
2. **Planning:** scope, resources, milestones, dependencies, cross-team alignment.
3. **Execution:** build, test, review, iterate with continuous stakeholder alignment.
4. **Release:** deploy, verify, announce.
5. **Close & Retrospective:** capture learnings and next steps.

## Communication Cadence
- **Weekly sync** between PM + PdM (+ DevOps if release-relevant)
- **Twice-weekly standups** for delivery team (or as agreed)
- **Design reviews** with UX Designer, Developers, and Product Manager
- **Pre-release QA sign-off** with QA, Developers, and Product Manager
- **Monthly stakeholder updates**
- **Ad-hoc escalations** as needed
